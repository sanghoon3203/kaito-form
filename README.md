# kaito-form

BAQOOL サポートのお問い合わせフォームです。図面と案件の情報を受け付けます。サーバーは PHP だけで動きます。ブラウザで動く JavaScript は、Cloudflare Turnstile(ボット対策)と、図面ファイルの一覧(1つずつ追加し、× で外せる)だけです。一覧の JavaScript が動かないブラウザでは、通常のファイル選択欄が使われます。

## 全体の流れ

1. 利用者が `public/index.php` のフォームに会社名・案件情報・図面の希望納期を入力し、図面(PDF・JWW)を添付して送信します。
2. `public/index.php` が入力とファイルを確かめ、ボット対策を通ったら、Google Apps Script(`Code.gs`)に受付を依頼します。
3. `src/lib.php` が図面を Google ドライブの「会社名/案件名」フォルダに保存します。
4. `Code.gs` が受付一覧のシートと、案件管理表の「案件基本情報」に1行ずつ追加し、通知メールを送ります。
5. 受付が終わると `public/complete.php` に移ります。

## ファイルの構成

| パス | 内容 |
|---|---|
| `kaito-form.php` | WordPress プラグインとしての入口 |
| `public/` | WordPress を使わないときに公開フォルダに置くもの(`index.php`・`complete.php`・`.htaccess`) |
| `src/` | フォームの本体(処理・画面・ロゴ)。ブラウザからは開けないようにしてあります |
| `data/` | 送信回数の記録と使用済みトークン。自動で作られます |
| `Code.gs` | Google Apps Script |

ロゴは画面の HTML に埋め込んで表示します。画像ファイルを公開フォルダに置く必要はありません。

## 必要なもの

- PHP 7.4 以上(curl・mbstring・openssl 拡張)
- php.ini でのアップロードの上限。`upload_max_filesize` は 8M 以上、`post_max_size` は 90M 以上(添付の合計80MBに、入力欄の分を足した値)、`max_file_uploads` は 10 以上にします。これより小さい設定だと、フォームに表示する上限も自動でその値まで下がります

## WordPress に設置する

1. プラグインの zip を作ります。

   ```
   git archive --format=zip --prefix=kaito-form/ -o kaito-form.zip HEAD kaito-form.php src
   ```

2. WordPress の管理画面で「プラグイン → 新規追加 → プラグインのアップロード」から zip を入れ、有効化します。
3. 「設定 → Kaito Form」に、Apps Script の URL・共有シークレット・Turnstile のサイトキーとシークレットキーを入れます。
4. 固定ページの本文に `[kaito_form]` と書いて公開します。そのページがフォームになります。

フォームのページは、テーマのヘッダーやフッターを通さずに、フォームの画面だけを表示します。テーマの CSS や JavaScript と混ざらないので、デザインも、スクリプトを制限するセキュリティ設定(CSP)も、単独で置いたときと同じです。

- 送信回数の記録などは `wp-content/uploads/kaito-form/` に保存し、ブラウザからは開けないようにします。
- WordPress が送信内容に足す `\` は、プラグインが外してから処理します。
- フォームのページは、キャッシュしないように指示を出します。サーバー側のキャッシュ(Xserver の Xアクセラレータなど)を使っている場合は、フォームのページを対象から外してください。キャッシュされると、2人目以降が送信できなくなります。

## WordPress を使わずに設置する

1. `public/` の中身を公開フォルダに置き、その一つ上の階層に `src/` を置きます。
2. `.env.example` を写して `.env` を作り、値を入れます。`.env` も公開フォルダの一つ上に置きます。
3. 公開フォルダの一つ上に、PHP が書き込める `data/` フォルダを作ります。作れない場合は、`.env` の `DATA_DIR` に書き込める場所を指定します。
4. Cloudflare の Turnstile 画面でウィジェットを作り(またはいまのウィジェットを使い)、ホスト名に設置先のドメインを追加します。サイトキーとシークレットキーを `.env` に入れます。

## ボット対策

次の対策を組み合わせています。

- Cloudflare Turnstile で、送信者が人かどうかを確かめます。結果は PHP が Cloudflare に問い合わせて確かめるので、ブラウザ側の判定だけを信用することはありません。

- 人には見えない入力欄を置き、そこに何か入っていれば受け付けません(ボットはすべての欄を埋めがちなため)。
- フォームを表示するときに署名付きのトークンを発行し、表示から3秒未満の送信と2時間を過ぎた送信を受け付けません。
- トークンは一度しか使えません。送信ボタンの二度押しや、ブラウザの再読み込みによる重複送信も防ぎます。
- 同じ IP アドレスからの送信は、1時間に5回までです(`.env` の `RATE_LIMIT_PER_HOUR` で変えられます)。IPv6 は、利用者が同じ /64 の中でアドレスを変えられるので、/64 ごとに数えます。
- 同じ送信元からのアップロード量は、1時間に合計300MBまでです(`CLIENT_UPLOAD_MB_PER_HOUR`)。
- 送信元を変えながら大量に送られた場合に備え、全体でも1時間に200件、アップロード量の合計10240MBまでに制限します(`GLOBAL_LIMIT_PER_HOUR`・`GLOBAL_UPLOAD_MB_PER_HOUR`)。上限に達すると「混み合っております」と表示します。全体の上限を送信元ごとの上限に近づけると、少数の送信元だけで受付全体を止められてしまうので、十分大きくしておきます。
- 上限はすべて先に確かめてから数えます。上限で断られた送信は数えません。受付処理に入った後の失敗は、わざと失敗させて上限を逃れられないように、数えたままにします。

サイトを Cloudflare 経由で公開している場合は、Cloudflare の WAF で `POST` の回数制限も設定すると、さらに守れます。なお、Cloudflare などのプロキシを通すと、PHP から見える IP アドレスがプロキシのものになり、利用者全員が同じ IP として数えられます。その場合は、`RATE_LIMIT_PER_HOUR` を大きくして、送信元ごとの制限は WAF に任せてください。

## Apps Script(Code.gs)

Google Apps Script のプロジェクトに `Code.gs` を貼り、ウェブアプリとしてデプロイします。Drive API(高度なサービス)を有効にしてください。Script Properties に次を設定します。フォルダやスプレッドシートの ID の欄には、ブラウザのアドレス欄の URL をそのまま貼ってもかまいません。

| キー | 内容 |
|---|---|
| `SHARED_SECRET` | `.env` の `SHARED_SECRET` と同じ値 |
| `ROOT_FOLDER_ID` | 図面を保存するドライブのフォルダ ID |
| `SHEET_ID` | 受付一覧のスプレッドシート ID |
| `NOTIFY_EMAIL` | 通知メールの宛先 |
| `CASE_SHEET_ID` | 案件管理表のスプレッドシート ID。未設定なら案件管理表には書き込みません |
| `CASE_SHEET_NAME` | 書き込むシート名。省略すると「案件基本情報」 |
| `HOLIDAY_CALENDAR_IDS` | 会社の休業日を入れた Google カレンダーの ID(カンマ区切り)。省略すると日本の祝日だけ |
| `DESIGN_SHEET_ID` | 設計用・顧客管理のスプレッドシート ID。未設定なら書き込みません |

案件管理表を共有ドライブへ移したときは、`CASE_SHEET_ID` を新しい ID に変えるだけで切り替わります。Apps Script を動かすアカウントに、そのファイルの編集権限が必要です。

## 案件基本情報への書き込み

書き込む列は、1行目のヘッダー名で探します。列を追加したり並べ替えたりしても、ヘッダー名が同じなら正しい列に入ります。フォームの入力は次のヘッダーの列に入り、それ以外の列(案件番号・ステータス・金額・入金など)は空欄のままにして社内で入力します。

| ヘッダー名 | フォームの入力 |
|---|---|
| 顧客名 | 会社名 |
| 顧客支店名 | ロゴスホームのときだけ書きます。入力した支店名をプルダウンの表記に合わせます(例:札幌北 → LH札幌北、函館 → LH函館、カフェ函館 → HC函館)。どれか決められなければ空欄 |
| 案件名 | 姓と名を全角スペースでつないだもの(例:山田　太郎) |
| 案件住所 | 都道府県・市区町村・丁目番地をつないだもの |
| 床下暖房種別 | 放熱器・AC・ﾌｧﾝｺﾝﾍﾞｸﾀｰ |
| 着工予定日 | 着工予定日 |
| 完工予定日 | 完工予定日 |
| 備考 | フォームの備考だけ。担当者・連絡先・図面のリンク・【要注意】は受付一覧と通知メールに残します |

顧客住所(自動)のような自動の列には値を書かず、直前の行に数式があれば同じ数式を入れます。次の値は、空欄にせず備考に書き残します。

- ヘッダーが見つからない項目の値
- 顧客名のプルダウンにない会社名など、入力規則に合わない値。プルダウンとは「株式会社」「㈱」や空白の違いを無視して照らし合わせ、合えばプルダウンの表記で書きます(例:「株式会社 豊栄建設」→「豊栄建設㈱」)

「備考」のヘッダーが見つからないときは書き込みをやめ、通知メールで手入力を促します。

## 入力欄

備考のほかは、すべて必須です。完工予定日は、着工予定日より後の日付でなければ送信できません。納期の短縮は、希望しない・1営業日(+3万円)・2営業日(+2万円)・3営業日(+1万円)から選びます。短縮を選んだ受付は、通知メールの件名に【納期短縮】が付きます。選択肢は `src/lib.php` の `RUSH_OPTIONS` で変えられます。

## 案件番号と設計用・顧客管理への書き込み

受付ごとに案件番号を1つ作り、案件管理表と設計用・顧客管理に同じ番号を書きます。番号は「B + 年月(4桁) + - + 3桁の連番」で、月ごとに001から数えます(例:B2611-010)。両方のシートの全タブから今月の一番大きい番号を探し、その次の番号にします。

設計用・顧客管理では、会社名に「豊栄」「ロゴス」「生杉」「竹内」が入っていればそのタブに、どれにも当たらなければ「その他」に書きます。書く列は、支店(名)・顧客名(施主様のお名前)・依頼者・PDF依頼日(受付日)・CAD依頼日(JWW ファイルが届いたときだけ、PDF依頼日と同じ受付日)・図面納品日(納品予定日)・引渡日(完工予定日の年月)・案件番号、その他タブでは会社名です。作図担当・ステータス・設計料などは空欄のままにします。見出しが空の1列目(豊栄建設のA列)は顧客名として扱います。

支店は、ロゴスホームでは「支店」列に書き、その他タブでは備考に書きます(例:新潟支店)。豊栄建設・生杉建設・竹内建設には書きません。床下暖房種別は、どのタブでも備考に「床下AC」のように書きます。備考には、このほかに納期の短縮を選んだときのその内容(例:納期短縮：1営業日（+3万円）)と、フォームの備考だけを書きます。複数あるときは「床下放熱器/二世帯住宅」のように / で区切って1行にします。ステータスは空欄のままにします。

見積り額タブの集計式が壊れないよう、最終行の上に行を挿入してから最終行と入れ替え、新しい受付を一番下に置きます。

## 納品予定日

フォームは、図面の納品予定日を営業日で計算して表示し、設計用・顧客管理の「図面納品日」に書きます。

- 営業時間は平日 8:30〜17:30 です。17:30 を過ぎた申し込みと、土日・祝日の申し込みは、翌営業日の受付として数えます。
- 受付日は数えません。作図に、短縮なしは4営業日、短縮ありは選んだ営業日数(1〜3)かかり、その次の営業日が納品予定日です。短縮なしで希望納期がそれより後なら、希望納期を納品予定日にします。短縮なしで、それより早い希望納期は送信できません。希望納期が土日・祝日・休業日のときは、次の営業日を納品予定日にします。
- 例:金曜 15:00 に「1営業日」で申し込むと、月曜に作図して、納品予定日は火曜です。金曜 17:31 なら受付が月曜になり、納品予定日は水曜です。
- 納期の短縮を選んだときは、希望納期がその日付と同じでなければ送信できません(画面で赤く知らせ、PHP でも確かめます)。
- 画面では、納期の短縮を選ぶと希望納期がその日付に変わり、通常の納期より早い希望納期を選ぶと、間に合う短縮が自動で選ばれます。
- 休みの日は、Google カレンダーから1日1回取ります。「日本の祝日」は自動で含め、会社の休業日は `HOLIDAY_CALENDAR_IDS` のカレンダーに終日の予定として入れます。カレンダーを直してからフォームに反映されるまで、最大1日かかります。
- Google に接続できないときは、`src/lib.php` の `HOLIDAYS`(2027年までの祝日)で計算します。

## 通知メール

通知メールは HTML のカード形式で送り、受け付けた図面ファイルを添付します。シートへの登録は、失敗したときだけ本文で知らせます。【要注意】になったファイルと、合計18MBを超える分は添付せず、本文にファイル名を書きます。その場合は Google ドライブで確認してください。

## 添付ファイルの安全対策

- 添付できるのは、PDF と JWW を合わせて10個まで、1ファイル8MBまで、合計80MBまでです(`src/lib.php` の `MAX_FILES`・`MAX_FILE_SIZE`・`MAX_TOTAL_SIZE`)。1ファイルの上限は `Code.gs` でも確かめます。
- ファイルの先頭が `%PDF-`(PDF)または `JwwData.`(JWW)で始まらないものは、Google ドライブに送る前に止めます。拡張子だけを変えた実行ファイルなどを防ぐためです。
- 受付の記録前に、`Code.gs` もドライブに保存されたファイルの先頭をもう一度確かめます。形式が合わないファイルはゴミ箱に移し、【要注意】として知らせます。
- 受付の記録前に、`Code.gs` が PDF の中から、開いたときに動作を起こせる要素(`/JavaScript`、`/Launch`、`/EmbeddedFiles` など)を探します。正常な図面にも入ることがあるので受付は止めません。見つかったときは、通知メールの件名に【要注意】を付け、本文と受付一覧の「要注意」列に書き残します。
- この検査は、圧縮された部分に隠された要素までは見つけられません。添付ファイルは、なるべくダウンロードせずに Google ドライブのプレビューで確認してください。

## 動作確認

```
php tests/smoke.php
php tests/delivery.test.php
php tests/wp-plugin.test.php
node tests/case-row.test.js
```

`smoke.php` は、`public/` と偽の Apps Script・偽のドライブ送信先をローカルで起動し、フォームの送信を通しで確かめます。入力チェック、ファイル形式のチェック、ボット対策も含みます。Google ドライブへの実際のアップロードは確かめません。

`delivery.test.php` は、納品予定日の計算を確かめます。`wp-plugin.test.php` は、WordPress の代わりになる小さなスクリプトの上で、プラグインの入口を通しで確かめます。本物の WordPress と管理画面の設定ページは確かめません。

`case-row.test.js` は、案件基本情報を真似た偽のシートで `Code.gs` の書き込みと PDF の検査を確かめます。
